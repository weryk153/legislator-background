# /donors 排序與篩選 設計

日期：2026-07-23
狀態：已核准
前置：docs/superpowers/specs/2026-07-23-donor-lookup-design.md（已上線）

## 目標

`/donors` 頁加三個控制項：排序（現任受贈人數／捐贈總額）、受贈者政黨篩選、受贈者職務篩選。只動前端（`DonorSearch.svelte`＋抽出的純函式模組），資料管線不變。

## 控制列（搜尋框下方，三個 select）

- 排序：`現任受贈人數`（預設）／`捐贈總額`
- 政黨：`全部政黨` ＋ 從 donors.json 內有連結受贈者（slug 非 null）動態收集的 distinct 政黨（依出現次數降冪）
- 職務：`全部職務`／`立委`／`議員`／`縣市長`

## 篩選語意（核心規則）

政黨/職務篩選只作用於**有連結的現任受贈者**（slug 非 null）；落選人（slug null）在任何篩選啟用時一律排除。

- 篩選啟用時，公司的「現任人數」「總額」以**符合條件的受贈者子集合重新計算**；展開卡片只列符合的受贈者，卡片列表上方顯示提示：「篩選中：僅列符合條件之受贈者與其金額」。
- 排行榜維持「符合條件現任 ≥2 位」門檻與 top 50；篩選後不足者自然消失。
- 無任何篩選時行為與現行完全相同（含落選人顯示、總額為全額）。
- 排序切換同時作用於預設排行與公司搜尋結果（人數 desc→總額 desc，或總額 desc→人數 desc）。
- 政治人物搜尋結果吃政黨/職務篩選（依 official 本人屬性），排序固定獻金總收入 desc。

## 實作形狀

- 純邏輯抽到 `src/lib/donorFilter.ts`：`matchRecipient`、`donorView`（回傳篩選後 recipients/人數/總額）、`rankDonors`、`filterOfficials`、`collectParties`——vitest 可測。
- `DonorSearch.svelte` 只做 UI 綁定與呼叫。

## 測試

- donorFilter 單元測試：無篩選＝原值；政黨/職務子集合重算；落選人在篩選時排除；≥2 門檻；兩種排序；officials 篩選。
- build＋瀏覽器實測（排序切換、篩政黨後金額變化、提示文字）。

## 增補（2026-07-23）：選舉篩選

使用者要求追加第四個控制項「選舉」：

- select 選項＝**粗分類**（使用者回饋：不用分到縣市）：「立委選舉」「議員選舉」「縣市長選舉」「議員補選」（固定順序、只列資料中存在者），前置「全部選舉」。分類器 `electionGroup(選舉名稱)` 依名稱關鍵字歸類。
- 篩選語意與政黨/職務相同：作用於受贈紀錄（依 recipient.election），啟用任一篩選時匿名/落選人排除規則不變（選舉篩選本身不限定 slug，落選人的紀錄也有選舉名——**選舉篩選單獨啟用時不排除落選人**，僅政黨/職務啟用時才排除；三者可 AND 組合）。
- 公司的人數/總額依符合子集合重算；排行門檻與提示文字沿用。
- 政治人物搜尋結果不吃選舉篩選（officials 索引無選舉維度——其 totalIncome 為跨選舉總額），篩選啟用時政治人物區顯示原結果。
