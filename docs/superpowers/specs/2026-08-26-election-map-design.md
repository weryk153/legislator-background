# 2026 九合一選舉分頁與政治地圖 設計 spec

**目標**：新增獨立分頁 `/elections`，以一張可逐層下鑽的全台政治地圖呈現九合一選舉。本輪先做**現況地圖**（現任者的政黨版圖，下鑽至村里）；候選人名單與開票結果留待資料出現後另案接上。

**選舉日**：2026-11-28。候選人登記期依過往慣例落在投票日前約兩個月（2026 年 9 月底至 10 月初），在那之前中選會不會有候選人名單，故本 spec **不涵蓋**候選人與開票結果。

**技術棧**：沿用 Astro 5 ＋ Svelte 5（runes）。新增前端依賴 `d3-geo`、`topojson-client`；新增建置期開發依賴 `mapshaper`（SHP → TopoJSON、簡化）。不引入地圖引擎（MapLibre／deck.gl）。

---

## 1. 範圍

### 1.1 本輪做

- 九種公職的**現任者**政黨版圖，三層下鑽：全國（22 縣市）→ 鄉鎮市區（368）→ 村里（約 7,740）。
- 各層級的席次結構統計（議會、代表會的政黨組成）。
- 縣市長**連任限制**判定：2018 與 2022 皆當選者，2026 不得再選。
- 縣市長、縣市議員連回站上既有檔案頁；鄉鎮市長以下明確標示「無背景資料」。

### 1.2 本輪不做

- 候選人名單、政見、開票結果、選前選後比較（資料尚不存在）。
- 立法委員（不屬九合一）。
- 得票率的地理熱區圖（本輪只上政黨色）。

### 1.3 為什麼下鑽到村里可行

疑慮曾是「7,740 個多邊形手機吃不消」。該疑慮的前提是一次全畫，但本設計是**分層載入**：全國畫面只有 22 格；點進縣市才抓該縣市的鄉鎮市區；再點才抓該鄉鎮市區的村里。單一畫面的多邊形數：全國 22、縣市層 5–39、鄉鎮市區層平均 21。

村里切檔切到**鄉鎮市區**層而非縣市層：368 份平均每份 21 格、數十 KB，點下去幾無延遲；若切成 22 份則平均每份 350 格、數百 KB。

## 2. 資料來源

### 2.1 中選會投開票資料（已在本機）

`scraper/out-roster/cec/voteData/2022-111年地方公職人員選舉/`，2026-08-26 清點如下。所有 CSV 為 UTF-8（非 Big5）、無標頭列。

| 代碼 | 公職 | 候選人 | 當選 |
|---|---|---|---|
| C1 | 直轄市長／縣市長 | 89 | 21 |
| T1 | 直轄市議員／縣市議員（區域） | 1,524 | 837 |
| T2 | 議員（平地原住民） | 73 | 34 |
| T3 | 議員（山地原住民） | 80 | 35 |
| D1 | 鄉鎮市長 | 489 | 198 |
| D2 | 直轄市山地原住民區長 | 20 | 6 |
| R1 | 鄉鎮市民代表 | 3,225 | 2,001 |
| R2 | 代表（平地原住民） | 134 | 70 |
| R3 | 直轄市山地原住民區民代表 | 92 | 50 |
| V1 | 村里長 | 14,021 | 7,740 |

當選合計 10,992 席。C1 為 21 席而非 22，因嘉義市長選舉遇候選人於投票前過世而延後重行選舉，其資料另存於 `scraper/out-roster/cec/2022年_嘉義市長重行選舉/`。

C1、T1、T2、T3 之下再分 `city/` 與 `prv/` 兩個子目錄（直轄市與省轄縣市），其餘類別無此分層。解析時兩者一併讀入。

補選資料在 `scraper/out-roster/cec/鄉鎮市長及議員補選(2023年後)/`，用於修正現任者。

#### 欄位語意（自資料驗證，非依文件推定）

**elbase.csv**：`省市別, 縣市別, 選區別, 鄉鎮市區別, 村里別, 名稱`

```
00,000,00,000,0000,全國
09,007,00,000,0000,連江縣
09,007,00,010,0000,南竿鄉
09,007,00,010,0001,介壽村
```

同一份檔案內同時含縣市、鄉鎮市區、村里三級，以後段代碼是否為 `000`／`0000` 區分層級。

**elcand.csv**：`省市別, 縣市別, 選區別, 鄉鎮市區別, 村里別, 號次, 姓名, 政黨代號, 性別, 出生日期(民國), 年齡, 出生地, 學歷, 是否現任(Y/N), 當選註記(*), 副手註記`

```
10,005,00,000,0000,1,鍾東錦,999,1,0520102,59,臺灣省,大學,N,*,
```

**elpaty.csv**：`政黨代號, 政黨名稱`。`999` 為無黨籍。

**elctks.csv**：各投開票所得票。本輪只用於村里層的得票率，不做投開票所層級。

### 2.2 行政區界線

內政部國土測繪中心之縣市界、鄉鎮市區界、村里界圖，授權為政府資料開放授權條款（可自由使用，須標示來源）。

**必須取選舉當時的版本**：村里界逐年變動（併村、改名、調整）。要與 2022 選舉結果對得上，須用 2022 年底版；2026 開票後再取當年版。取用日期與版本記入 `src/data/map/meta.json`。

授權標示比照站上照片授權的既有做法：地圖角落標示來源，「關於」頁列出完整授權條款。

### 2.3 兩邊的對應

中選會用自己的 `省市別/縣市別/鄉鎮市區別/村里別` 代碼，內政部界線檔用行政區代碼，兩套代碼不通用。`elbase.csv` 提供完整名稱路徑，故以**「縣市名＋鄉鎮市區名＋村里名」複合鍵**對應，該鍵在全國唯一（單以村里名不唯一，如「中山里」全台數十個）。

名稱差異須正規化後比對：臺／台、鄉鎮市區的全半形、界線檔可能用「臺北市大安區」而中選會用「大安區」。正規化規則寫成純函式並測試；**比對不到的一律列報，不做模糊猜測**——猜錯會把某村的村里長掛到另一村頭上，與本站既有的「常見名寧缺勿錯」原則同一類風險。

## 3. 模組切分

### 3.1 `scraper/lib/cecVoteData.ts`（純函式，無 I/O）

| 匯出 | 職責 |
|---|---|
| `parseElbase(csv)` | → `AreaNode[]`，含代碼、名稱、層級（county／town／village） |
| `parseElcand(csv)` | → `Candidate[]`，含姓名、政黨代號、性別、出生年、學歷、是否現任、是否當選、所屬區代碼 |
| `parseElpaty(csv)` | → `Map<政黨代號, 政黨名稱>` |
| `areaKey(county, town, village)` | 產生複合鍵；同時負責名稱正規化 |
| `winnersByArea(cands, areas)` | 依區彙整當選者 |

### 3.2 `scraper/lib/electionRules.ts`（純函式，無 I/O）

| 匯出 | 職責 |
|---|---|
| `termLimited(history)` | 縣市長是否已連任一次而不得再選 |
| `seatBreakdown(winners)` | 政黨席次統計（含無黨籍） |

連任限制的判定條件：**同一人、同一縣市、連續兩屆當選**（地方制度法第 55、56 條「連選得連任一次」）。非連續兩屆（中間隔屆）不受限。

「同一人」不可只靠姓名比對——中選會資料同名者眾。`elcand.csv` 有出生日期欄，以**姓名＋出生日期**認定，兩者皆同才算同一人；只有姓名相同者列報待查，不逕自認定。

改制升格（如 2010 年縣市合併改制直轄市）不併入計算：改制後為新設地方自治團體，任期重新起算。此情形在 2018→2022 這個判定區間內並未發生，故本輪不需處理，僅在此記明，以免日後誤把「合併計算」當成通則。

### 3.3 `scraper/build-election-map.ts`（有 I/O）

流程：讀十類 CSV → 合併現任者 → 套用補選與嘉義市長重行選舉修正 → 讀 TopoJSON → 依複合鍵合併 → 輸出分層檔。

輸出至 `src/data/map/`：

```
meta.json              界線檔版本、中選會資料年度、產生日期
national.json          22 縣市界 + 各縣市首長、議會席次結構
county/<代碼>.json     該縣市的鄉鎮市區界 + 鄉鎮市長、代表會席次
town/<代碼>.json       該鄉鎮市區的村里界 + 村里長
```

檔名的 `<代碼>` 一律使用**中選會代碼**（縣市為 `省市別-縣市別`，如 `10-005`；鄉鎮市區再接 `鄉鎮市區別`，如 `10-005-010`），不使用內政部行政區代碼。理由是整條管線由 `elbase.csv` 驅動，界線檔只是被合併進來的一方；用中選會代碼可讓輸出檔與來源資料直接對照，出錯時容易追。

### 3.4 `src/components/ElectionMap.svelte`

Svelte 5 runes，比照既有 `RelationshipGraph.svelte` 的寫法。職責：投影與繪製 SVG path、處理下鑽與返回、鍵盤操作、深色模式（用既有 CSS 變數，不自帶配色常數）。

資料取得走 `fetch` 分層載入，不在建置期全部塞進頁面。

### 3.5 `src/pages/elections.astro`

頁面骨架、倒數、麵包屑、側欄統計。導覽列在 `src/layouts/Base.astro` 加一項「選舉」。

## 4. 介面要求

### 4.1 資料深度必須看得出來

縣市長與縣市議員連得到檔案頁（判決、爭議、財產、政治獻金）；鄉鎮市長以下只有中選會欄位。介面上須以視覺區分，不可讓使用者以為每格點進去都有東西。

### 4.2 無黨籍佔多數的層級

村里長絕大多數為無黨籍，上色後接近一片中性色。這是事實而非缺陷，不以配色技巧掩飾；側欄同時列出該區無黨籍比例。

### 4.3 資料年度標示

現況地圖的內容是 2022 年選舉結果加補選修正，不是即時資料。頁面須明確標示，避免誤讀為 2026 的狀態。

## 5. 測試

純函式走 TDD：

- CSV 三種格式的解析，含空欄位與尾端空白。
- 複合鍵在全國範圍唯一（以實際 elbase 全量驗證）。
- 名稱正規化（臺／台、全半形、縣市前綴有無）。
- 現任者推導，含補選覆蓋原有當選者。
- 連任限制判定：連續兩屆受限、隔屆不受限、改制升格視為同一職位。
- 席次統計含無黨籍。

界線檔對應須有一個**全量比對測試**：所有中選會行政區都要對到界線檔的多邊形，對不到的列出清單。此測試允許有已知例外清單（如界線檔缺漏的離島），但例外須逐筆列名，不可用比例門檻放過。

地圖元件不寫單元測試，以建置後實際開頁面驗證下鑽、返回、鍵盤操作與深色模式。

---

## 6. 交付順序

1. `cecVoteData.ts` ＋ 測試（不碰界線檔，先確定資料讀得對）。
2. `electionRules.ts` ＋ 測試。
3. 界線檔取得、mapshaper 轉檔與簡化，全量對應測試。
4. `build-election-map.ts` 產出分層資料。
5. `ElectionMap.svelte` ＋ `elections.astro` ＋ 導覽列。
6. 「關於」頁補上界線檔授權標示。

第 1、2 步不依賴外部下載，可先完成。第 3 步是唯一的外部相依，若界線檔取得受阻，前兩步的成果仍然有效。
