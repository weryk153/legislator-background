# 開發與資料更新

給要在本機執行、修改程式或更新資料的人。一般讀者請看 [README](../README.md)。

## 架構

- **前台**：[Astro](https://astro.build/) 靜態產生，互動部分（列表篩選、選舉地圖、關係圖）為 Svelte 元件。執行期不連任何資料庫、沒有後端。
- **資料**：建置時讀已 commit 的快照（`src/data/officials.json`、`src/data/graph.json`、`public/data/**`），任何機器或 CI 都能建置。快照由本機 [Supabase](https://supabase.com/)（Postgres）匯出。
- **部署**：Cloudflare Pages，push 到 `master` 即自動重建。push 其他分支會產生公開的預覽網址，未審定的資料請勿 push。
- **網址**：個人頁為 `/officials/<slug>/`，slug 由姓名、職務、選區決定，重建不會變。

```
爬蟲（scraper/）→ 本機 Supabase → export:data → src/data/*.json → astro build → dist/ → Cloudflare Pages
```

## 本機執行

需 Node 22（見 `.nvmrc`）與 [pnpm](https://pnpm.io/)。

```bash
pnpm install
pnpm dev     # 本機開發（讀快照，不需資料庫）
pnpm build   # 產生靜態站到 dist/
pnpm test    # vitest
```

## 更新資料（需本機 Supabase）

本機 Supabase 跑在 Docker（本專案用 OrbStack），`supabase start` 後 API 在 `http://127.0.0.1:54421`（見 `.env`）。

| 指令 | 用途 |
|---|---|
| `pnpm run scrape` → `pnpm run scrape:import` | 爬蟲 → 人工審核 `scraper/out/*.json` → 匯入資料庫 |
| `pnpm run seed:from-json` | 從快照還原人工策展的爭議／判決 |
| `pnpm run judgments:record` | 寫入人工確認的判決（`scraper/judgments-confirmed.json`） |
| `pnpm run controversies:record` | 寫入人工核准的爭議（`scraper/controversies-confirmed.json`） |
| `pnpm run roster:record` | 名冊修正（新增、離任、更名；`scraper/roster-confirmed.json`） |
| `pnpm run donations:record` | 政治獻金（監察院 ardata） |
| `pnpm run export:data` | 匯出 → `src/data/officials.json`、`meta.json` |
| `pnpm run append:relationships` | 關係資料唯讀預檢；加 `--apply` 才增量寫入本機資料庫 |
| `pnpm run export:graph` | 匯出人物關係 → `src/data/graph.json` |
| `pnpm run build:election-map` | 選舉地圖資料（中選會 2018／2022 投開票資料 → `public/data/map/`） |
| `pnpm run build:candidates -- --stage <階段>` | 2026 候選人名單（中選會名冊 PDF → `public/data/candidates/2026/`），附差異報告 |

判決、爭議、名冊修正都採「確認檔」模式：人工查證後把結果寫進對應的 `*-confirmed.json`，再由腳本寫入資料庫；腳本可重跑、會去重。

排程刷新與司法院判決開放資料 feed 見 `.github/workflows/`。

### 新增人物關係

逐筆查核公開來源後，將關係加入 `scraper/relationships-curated.json`。新增列須有固定 UUID `id`、查核日 `reviewedAt`、名冊 `subjectId`，對象為公職人物時另填 `counterpartId`；議員與同名立委不能只靠姓名匹配。維基來源另記錄 `sourceRevision`，方便回查當時版本。歷史任職用「曾任」描述，不推定目前仍有幕僚或政治關係。

名冊外人物的固定 ID 登記在 `scraper/entity-identities.json`，鍵為姓名或 `姓名::counterpartDistinct`，須核對職務與身分後才重用。增量匯入保留既有人物、照片、來源與關係；先完整驗證，再建立缺少的端點、來源、關係。中途失敗可重跑，已存在且一致的紀錄會略過，內容衝突則中止。

```bash
pnpm run append:relationships          # 唯讀預檢
pnpm run append:relationships --apply  # 寫入本機 Supabase
pnpm run export:graph                  # 更新網站快照
```

舊的 `import:relationships` 會清除再重建非判決關係，日常追加請用上述增量流程。重建流程也沿用固定人物 ID，以保留人物查詢連結。

### 2026 政見收錄

政見策展快照為 `src/data/candidate-policies.json`，建置時直接讀取，不寫入 Supabase，
也不會被 `export:data` 或 `build:candidates` 覆蓋。
2026-10-16 完成登記名冊 81 位首長候選人的逐人盤點，累計收錄 75 人、112 筆公開紀錄、
289 項摘要、101 個來源，涵蓋全國 22 縣市；6 人仍待取得可核對的本屆政策來源。
本輪未擴充議員政見，也不宣稱已完整收錄任何候選人的所有政策。

逐人結果保存在 `src/data/candidate-policy-reviews.json`，包含名冊日期、查核日期、
收錄狀態、查詢詞與已閱讀的參考來源。`collected` 指部分主張已收錄，
`pending-source` 指本輪未取得可核對資料，不代表未發表。搜尋結果只作線索，
不把舊屆公報、彙整網站的AI摘要或現任施政成果直接當作2026競選政見。
完整覆蓋與待補說明見 [首長政見盤點](candidate-policy-audit-2026.md)。

增補時先核對報導中的本人及參選職位，使用名冊已有的 `slug`（現任立委參選市長仍用
原檔案 slug），填寫 `name`、`role`。每次發表新增固定 `id` 的紀錄，包含發表日
`announcedOn`、本站核對日 `reviewedOn`、來源類型／標題／網址／刊登日，以及按主題
改寫的 `proposals`。來源類型為 `news`（新聞）、`campaign`（本人或政黨競選資訊）、
`gazette`（選舉公報）、`civic`（公民團體公開承諾紀錄）。發表日記錄當次提出或重申，
不一定為首次提出；來源未載明確發表日時使用 `null`，顯示「來源未載明確日期」，
不得拿刊登日或查詢日冒充。來源刊登日仍須核對；官網政策頁未載時允許 `publishedOn: null`，頁面明示「未載日期」。共同報導逐人區分，合作承諾保留歸屬，
評估、爭取中央協助等條件不得刪除。更新 `updatedOn` 及相應的查核狀態；轉載不重複計數。

`src/lib/candidatePolicies.ts` 檢查姓名、slug、2026參選職位、重複ID、日期順序、來源與
非空摘要，並驗證查核表完整涵蓋首長名冊且狀態與實際收錄一致。名冊更新後須重新盤點。
個人頁的「2026 政見」置前，按發表日、來源刊登日、本站核對日依序作為排序依據；核對日不顯示為發表日；待補者顯示查核日期及說明。
首長卡片提供政見入口；摘要項數只是收錄量，不用於排序或評分。
修改後執行 `pnpm exec vitest run test/candidatePolicies.test.ts` 與 `pnpm build`，並檢查有資料、
待補來源、一般議員尚未收錄三種頁面，以及各縣市頁入口。

### 首次參選標記（2026-10-13）

候選人搜尋、地圖側欄、完整名冊、縣市頁與個人頁共用 `FirstRunBadge.svelte`。
標記定義為首次參選任何公職；未在任、未當選、首次選某職位、黨內新人加權，以及查無歷屆紀錄，都不足以自動判定。
`firstRun` 缺值代表尚未確認，不表示已有參選經驗。個人頁顯示年度，標記本身連到查證來源。

人工確認表為 `scraper/candidate-first-runs-confirmed.json`，每筆記錄姓名、人物 slug、完整選區、選舉年、定義範圍、公開來源與核對說明。

全國逐人查核底稿為 `scraper/candidate-first-run-audit.json`，涵蓋本次名冊的每一位候選人，區分 `first-run`（已有明確證據）、`previously-ran`（已核對本人曾參選公職）及 `unresolved`（完成本輪檢索但證據不足）。未確認不等於曾經參選，也不等於首次參選。查核範圍包含村里長、鄉鎮市民代表及不分區立委；同名歷史紀錄須核對身分，只有「新人」或「首次選議員」的文字不足以確認。

更新底稿後執行 `pnpm candidates:first-run-audit --write`，驗證名冊覆蓋、姓名與選區、年度、狀態及來源後產生人工確認表；再執行 `pnpm build:candidates --stage registration` 發布至候選人資料。唯讀盤點使用 `pnpm candidates:first-run-audit`。此命令不會自行以搜尋結果或姓名命中決定狀態。完整範圍與當次結果見 [2026 首次參選查核紀錄](first-run-audit-2026.md)。
`build:candidates` 在人物連結去重後，檢查所有確認資料的年度與身分，再將來源帶入候選人 JSON；不寫入公職任期或修改既有人物經歷。

### 候選人網站與 Facebook
