# 開發與資料更新

給要在本機執行、修改程式或更新資料的人。一般讀者請看 [README](../README.md)。

## 架構

- **同縣市縣市長政見比較**：各縣市頁直接在縣市長候選人卡片勾選「加入比較」，選滿兩位即展開下方完整政見並定位結果；不再提供重複的下拉選人欄。最多選兩位，取消勾選可替換，結果的「更換人選」回到卡片、「清除選擇」同步重設卡片。未滿兩位時隱藏比較表，卡片上顯示已選人數；分享連結留在該縣市頁並定位比較區，網址不能改變固定縣市。獨立比較介面與導覽入口已移除，舊 `/elections/2026/policies/` 網址只保留轉址，帶人選者回到原縣市比較，無縣市者回到找候選人；轉址頁不列入 sitemap。只由同縣市名冊選兩位不同候選人，無全國混合模式。網址中的跨縣市、重複或無效人選亦會排除。預設呈現完整已收錄政見，不單獨抽出交通或其他議題；關鍵字可同時縮小兩欄內容，未命中與尚未收錄分別提示。桌面及手機皆為雙欄並排、無水平捲動，姓名固定在上方；姓名連至完整人物頁，來源及日期按需展開。候選人卡片長姓名完整換行，避免窄螢幕溢出；剪貼簿不可用時顯示可選取的分享網址。`chiefPolicyComparisonData.ts` 以名冊 slug 與參選職位核對既有政見，全文及限定語保持原樣；沒有政見仍保留候選人。頁首與比較區的分享皆保留縣市、左右人選及關鍵字，上一頁可還原。搜尋分組與地圖側欄提供直達該縣市卡片的入口；從比較進入人物頁後，頁首與人物資料下方的返回連結皆保留原比較與關鍵字，並定位比較結果。未啟用 JavaScript 時仍可透過靜態名冊閱讀人物資料。沿用既有快照，未宣稱重新查核原始來源。交通議題試作頁與參照清單已移除。選舉頁重複的六都市長卡片亦已移除；搜尋、地圖、縣市頁與可展開的靜態完整名冊保留。

- **前台**：[Astro](https://astro.build/) 靜態產生，互動部分（列表篩選、選舉地圖、關係圖）為 Svelte 元件。執行期不連任何資料庫、沒有後端。
- **資料**：建置時讀已 commit 的快照（`src/data/officials.json`、`src/data/graph.json`、`public/data/**`），任何機器或 CI 都能建置。快照由本機 [Supabase](https://supabase.com/)（Postgres）匯出。
- **部署**：Cloudflare Pages，push 到 `master` 即自動重建。push 其他分支會產生公開的預覽網址，未審定的資料請勿 push。
- **網址**：個人頁為 `/officials/<slug>/`，slug 由姓名、職務、選區決定，重建不會變。
- **議員選區頁**：`/elections/2026/<county>/district-<no>/`，依當屆名冊編號產生 221 個選區頁，涵蓋 1,502 位議員候選人。範圍採既有公告核對資料；未核對者明示歷年行政區參考，不能當作 2026 正式選區範圍。
- **同選區候選人比較**：221 個議員選區頁內建 `CandidateComparison.svelte`，比較入口整合在「本區候選人」標題旁，以「比較候選人」按鈕開啟選人區，選好後按「開始比較」隱藏選單並顯示結果；可更換人物或結束比較。帶至少兩個有效 compare 選擇的連結直接顯示結果，一人時開啟選單。從當區名冊勾選 2～4 人，依目前選擇順序並排呈現學歷、經歷、2026 政見與政治獻金。以已核對的 slug 串接資料，保留名冊姓名與異體字；無檔案者不以姓名猜測配對。學歷沿用當屆公報優先規則與資格限定語，學歷紀錄不重複列入經歷；經歷先列三項，其餘可展開。來源／核對日期集中在比較表下方可展開的「資料來源與說明」，依人物及項目列出；政治獻金按原選舉及申報別分列、不合併、不把缺資料補零，也不做綜合評分。選擇以重複 `compare` 查詢參數保存，分享固定使用正式網域；重載及上一頁可還原，跨區、重複與超額選擇會過濾並提示。手機（760px 以下）固定兩欄並排、無水平捲動，四個項目按鈕切換學歷、經歷、政見、獻金；姓名照片固定在欄位頂端。勾選三至四人時可由欄位下拉選單換人，保留其他勾選者且禁止左右同人。前兩個 compare 參數代表手機目前對照人物，topic 參數保留目前項目，分享與上一頁可還原。手機與桌面共用內容渲染片段，來源及缺漏說明一致；桌面保留完整並排表格。介面不放重複解釋操作的標語；選擇人數、學歷年份、政見發表日期及金額申報別保留在比較欄，補充註記與來源日期移至可展開的「資料來源與說明」；姓名連結至完整人物頁，不再重複顯示人物資料按鈕。未開啟 JavaScript 仍保留下方靜態名單。名冊不足兩人時顯示無法同區比較。政見收錄仍主要為首長候選人，議員缺漏明示未收錄，不代表未發表。
- **分享**：`ShareActions.svelte` 提供系統分享、複製連結及可選的圖卡下載。候選人篩選、人物關係與票差結果可還原查詢狀態；對外分享網址使用正式網域。新增選區頁含 canonical、描述、結構化資料及 sitemap。
- **分享圖卡**：建置時生成 1,894 張人物卡及 221 張選區卡（1200×630 PNG），由個人／選區頁的 Open Graph 設定引用。資料日期沿用快照或來源日期；字型來源與快取說明見 [字型文件](../src/assets/fonts/README.md)。首次建置需逐張渲染，後續建置可使用 `node_modules/.astro/share-card-cache/`；Cloudflare Pages 必須啟用 Build cache，才能跨部署保留。
- **人物摘要卡**：摘錄最多兩項學歷及兩項不同經歷，附來源標題、歷年學歷來源年份與回到完整人物頁的 QR code。學歷沿用當屆公報優先規則；不截掉肄業等資格限定語，過長內容改提示查看全文。重複連任紀錄依原資料順序保留第一筆；空白資料明示「尚未收錄」。目前 1,791 頁有可呈現的背景、當選或申報資料並提供圖卡下載；其餘 103 頁僅提供分享連結。QR code 已以原始 PNG 實際解碼驗證，包含中文網址與長姓名。
- **直式下載卡**：人物頁下載 `/cards/{id}.png`，寬 1080、高度隨內容調整。採本站純白底、墨黑宋體與朱紅提示；左側大姓名、右側較大人像，長姓名依文字寬度換行、不水平壓縮。中段雙欄學經歷以標題、細線及條列分層；完整日期與羅馬字優先整段換行。呈現同一份學歷來源的較完整內容及不同經歷，排除已在標頭呈現的候選人登記紀錄，委員會職務排在其他經歷之後；容納不下的項目以實際剩餘筆數提示。當選年份依中選會資料繪製時間軸，不推定完整任期。最新已收錄財產申報摘錄與政治獻金收支集中在下方黑底數字區，附申報年份、選舉名稱及申報別；金額、筆數分開標示，財產保留自動解析與非總資產說明。未收錄不填零，不加宣傳標語。照片保留作者與授權；原始來源可經 QR code 回人物頁核對。社群 Open Graph 仍使用橫式 1200×630 卡。
- **選區下載卡**：221 區使用 `/cards/district-{county}-{no}.png`，共完整呈現 1,502 名登記者。照片索引版型沿用宋體、墨黑與朱紅，搭配淺米白背景；縣市／選區使用大字標題，登記人數置於紅底區塊。政黨比例條以全區名單人數為分母，每黨獨立呈現、不把小黨混成無黨籍，保留名冊出現順序。名單超過 9 人採四欄，其餘三欄，由左至右排列，未抽號次不自行編號。大照片下方為黑底姓名帶，再接政黨與任職／當選紀錄；同列照片、姓名帶、紀錄區與底部對齊，年份以完整四位數分組換行。照片依 slug 對應本站已落地人像，缺照以姓名首字與明確文字占位；Commons 署名在底部保留作者與授權。任期只採明確職稱及起訖日期；中選會當選紀錄僅列年份，不把選舉日或缺少結束日期推算成連續任期，缺資料也不標成未曾任職。圖卡寬 1080、高度依名單與內容調整；附名單階段、製表日期、範圍對照年份及回到該選區頁的 QR code。目前資料未核對 2026 應選席次，明示待核對，不以 2022 席次代替。

```
爬蟲（scraper/）→ 本機 Supabase → export:data → src/data/*.json → astro build → dist/ → Cloudflare Pages
```

## 本機執行

需 Node 22（見 `.nvmrc`）與 [pnpm](https://pnpm.io/)。

```bash
pnpm install
pnpm dev     # 本機開發（讀快照，不需資料庫）
pnpm build   # 產生靜態站到 dist/
pnpm audit:seo # 建置後檢查整站標題、靜態內容、canonical、分享圖與 sitemap
pnpm test    # vitest
```

SEO：選舉總覽標題與縣市摘要包含候選人查詢及已收錄政見比較；名冊與人物內容保留靜態 HTML。`robots.txt` 在建置時依 `Astro.site` 產生，與 canonical、sitemap 共用 `SITE_URL`。網站地圖省略無法可靠逐頁判定的 `lastmod`，不把人物快照匯出日套用到所有頁面。資料集來源說明使用 `citation`，不宣稱來源內容具有共同授權。舊比較頁維持 noindex 與相容轉址，404 不列入 sitemap。發布後仍須透過 Google Search Console 確認實際索引與搜尋成效，本機檢查不代表已被 Google 收錄。

### 候選人訪客表態

候選人個人頁、縣市首長卡片與議員選區卡片使用 `CandidateReactions.svelte`，只顯示 ↑／↓ 和累計數字；支持／不支持以 tooltip 與 accessible name 說明。選取後反白，重按取消，改選會移動該筆票數。名冊順序不受表態影響；用途與隱私說明見 `/about/#reactions`。

`/api/reactions` 是 Cloudflare Pages Function，使用 D1 共用計票；未連上服務時顯示不可用，不把失敗當作零票。`pnpm build` 先從當屆名冊產生 API 候選人白名單，再產生靜態站。所有資料與票數各自儲存，原本的本機 Supabase 不供公開 API 存取。

- 正式 Pages 專案需要 D1 binding `REACTIONS_DB`，並執行 `migrations/reactions/0001_reactions.sql`。
- 設定 secret `REACTION_SECRET`，至少 32 字元，使用密碼學隨機值。不得提交到 Git，也不設成 `PUBLIC_` 變數。正式與預覽環境使用不同的資料庫及 secret。
- 本機在已忽略的 `.dev.vars` 放入自己的 `REACTION_SECRET`，執行 `pnpm db:reactions:local`、`pnpm build`、`pnpm dev:reactions`，開啟 `http://localhost:4325`。`wrangler.local.jsonc` 僅用於本機資料表初始化，不能拿來發布。
- 一般 `pnpm dev`／`pnpm preview` 不會啟動 Pages Functions；要驗證計票需使用上述完整環境。

簽章 HttpOnly Cookie 的有效期是 180 天；資料列僅存依候選人分別 HMAC 的瀏覽器識別碼及目前選擇，取消直接刪除。相同訪客與候選人的唯一鍵，加上傳送最終選擇的 upsert，避免重送重複加票；寫入與回傳統計在同一個 D1 batch transaction。POST 檢查同源 Origin、JSON 格式、候選人白名單及內容大小。每個瀏覽器每 10 分鐘最多 60 次提交，來源 IP 另有 300 次配額；限速識別經 HMAC 處理，過期紀錄在後續提交時清除，不儲存原始 IP。這不是身分驗證或民調，仍可能透過清 Cookie、換裝置等方式再次表態。

`pnpm exec vitest run test/reactions.test.ts` 使用真正的 SQLite 驗證重送、改選、取消、並行請求、資料隔離、跨站拒絕、限速及錯誤回應；發布時另確認正式 API 可讀取且新資料庫沒有測試票。

## 更新資料（需本機 Supabase）

本機 Supabase 跑在 Docker（本專案用 OrbStack），`supabase start` 後 API 在 `http://127.0.0.1:54421`（見 `.env`）。

| 指令 | 用途 |
|---|---|
| `pnpm run scrape` → `pnpm run scrape:import` | 爬蟲 → 人工審核 `scraper/out/*.json` → 匯入資料庫 |
| `pnpm run seed:from-json` | 從快照還原人工策展的爭議／判決 |
| `pnpm run judgments:record` | 寫入人工確認的判決（`scraper/judgments-confirmed.json`） |
| `pnpm run controversies:record` | 寫入人工核准的爭議（`scraper/controversies-confirmed.json`） |
| `pnpm run roster:record` | 名冊修正（新增、離任、更名；`scraper/roster-confirmed.json`） |
| `pnpm run donations:record` | 政治獻金（監察院 ardata） |
| `pnpm run export:data` | 匯出 → `src/data/officials.json`、`meta.json` |
| `pnpm run append:relationships` | 關係資料唯讀預檢；加 `--apply` 才增量寫入本機資料庫 |
| `pnpm run export:graph` | 匯出人物關係 → `src/data/graph.json` |
| `pnpm run build:election-map` | 選舉地圖資料（中選會 2018／2022 投開票資料 → `public/data/map/`） |
| `pnpm run build:candidates -- --stage <階段>` | 2026 候選人名單（中選會名冊 PDF → `public/data/candidates/2026/`），附差異報告 |

判決、爭議、名冊修正都採「確認檔」模式：人工查證後把結果寫進對應的 `*-confirmed.json`，再由腳本寫入資料庫；腳本可重跑、會去重。

排程刷新與司法院判決開放資料 feed 見 `.github/workflows/`。

例行人物資料更新使用 `pnpm refresh:data`。它讀取既有 `officials.json`，對 1,043 個
scraper targets 查詢經歷與財產來源，再增量合併；不再從空 Supabase 資料庫重建人物。
人物固定 ID、slug、正名、任職狀態、照片、簡介、獻金、判決、爭議及名冊外的候選人
全部保留。更名僅接受 `roster-confirmed.json` 中同職務、同選區、有來源的已確認紀錄。
新的經歷依人物、機構、職稱、日期去重（相同日期的斜線與連字號視為相同）；財產只
新增缺少年份或補入空白金額，不覆寫已有金額。判決及爭議即使出現在已核准 review
中也不由此流程發布。

監察院姓名搜尋可能包含同名者，財產紀錄須同時符合姓名、服務機關與職務才自動
合併。例如臺北市議員許淑華不能套用南投縣長許淑華的公報；李柏毅的立法院與臺北市
議會申報也分開。來源標題記錄機關、職務與期別。其他職務時期的歷史申報不因同名
就自動新增，須另行查核；既有已整理的紀錄仍保留。

每次重新抓取全部來源，最多三個 worker；逐人證據與完成／失敗報告存於
`scraper/out-refresh/`（不提交 Git）。任一來源或身分驗證失敗，整批不寫入快照，日期
也不前進。只有資料實際改變時才更新 `meta.json`，workflow 驗證並建置後將兩個檔案
一起提交。人物資料彙整日、選舉名冊日、最新號次來源日分別顯示，不用單一日期暗示
所有內容都在同一天查核。

本機 Codex 排程每天台北時間 17:00 統一啟動人物基本資料、選舉名冊、號次與政見維護。
同一輪呼叫 GitHub `refresh-data.yml` 查詢人物來源，並同步查核官方名冊、號次、
政見與公告修正，涵蓋首長及議員；GitHub workflow 保留手動觸發，不再另設定時執行。
人物資料每次均查詢來源並執行合併驗證；有內容變更才重新建置、提交及部署，無變更
則保留原本日期。發布本機選舉／政見變更前，先確認雲端更新完成並安全整合遠端版本，
避免兩邊同時推送覆蓋。本機排程須保持電腦與 App 開啟；司法維護仍獨立於每日 00:25 執行。
政見依下方收錄規則核對本屆來源，保留發表日、來源刊登日及查核日的區別；沒有
可信新內容不新增紀錄或改寫資料日期，亦不重複通知。

立法院資料改用[官方歷屆委員資料集 ID16](https://data.ly.gov.tw/getds.action?id=16)，
每次執行只下載一次第 11 屆資料，依姓名與屆別精確篩選，避免匿名鏡像的頻率限制。
官方舊 TLS 端點相容處理僅限固定公開資料 URL，仍驗證憑證與主機名稱，不修改全域
TLS 設定，也不以該相容通道傳遞帳密。

PDF 文字擷取需 Poppler：Ubuntu 使用 `sudo apt-get install poppler-utils`，macOS 使用
`brew install poppler`。程式在轉換時依序找 `PDFTOTEXT_PATH`（完整執行檔路徑）、
`PATH`；macOS 也會找 `HOMEBREW_PREFIX/bin`、`/opt/homebrew/bin`、`/usr/local/bin`。
解析純文字或建置網站不需要安裝 Poppler。Refresh data workflow 會先安裝並檢查它。

### 新增人物關係

逐筆查核公開來源後，將關係加入 `scraper/relationships-curated.json`。新增列須有固定 UUID `id`、查核日 `reviewedAt`、名冊 `subjectId`，對象為公職人物時另填 `counterpartId`；議員與同名立委不能只靠姓名匹配。維基來源另記錄 `sourceRevision`，方便回查當時版本。歷史任職用「曾任」描述，不推定目前仍有幕僚或政治關係。

名冊外人物的固定 ID 登記在 `scraper/entity-identities.json`，鍵為姓名或 `姓名::counterpartDistinct`，須核對職務與身分後才重用。增量匯入保留既有人物、照片、來源與關係；先完整驗證，再建立缺少的端點、來源、關係。中途失敗可重跑，已存在且一致的紀錄會略過，內容衝突則中止。

pnpm run append:relationships --apply  # 寫入本機 Supabase
pnpm run export:graph                  # 更新網站快照

### 首次參選標記（2026-10-13）

候選人搜尋、地圖側欄、完整名冊、縣市頁與個人頁共用 `FirstRunBadge.svelte`。
標記定義為首次參選任何公職；未在任、未當選、首次選某職位、黨內新人加權，以及查無歷屆紀錄，都不足以自動判定。
`firstRun` 缺值代表尚未確認，不表示已有參選經驗。個人頁顯示年度，標記本身連到查證來源。

人工確認表為 `scraper/candidate-first-runs-confirmed.json`，每筆記錄姓名、人物 slug、完整選區、選舉年、定義範圍、公開來源與核對說明。

全國逐人查核底稿為 `scraper/candidate-first-run-audit.json`，涵蓋本次名冊的每一位候選人，區分 `first-run`（已有明確證據）、`previously-ran`（已核對本人曾參選公職）及 `unresolved`（完成本輪檢索但證據不足）。未確認不等於曾經參選，也不等於首次參選。查核範圍包含村里長、鄉鎮市民代表及不分區立委；同名歷史紀錄須核對身分，只有「新人」或「首次選議員」的文字不足以確認。

更新底稿後執行 `pnpm candidates:first-run-audit --write`，驗證名冊覆蓋、姓名與選區、年度、狀態及來源後產生人工確認表；再執行 `pnpm build:candidates --stage registration` 發布至候選人資料。唯讀盤點使用 `pnpm candidates:first-run-audit`。此命令不會自行以搜尋結果或姓名命中決定狀態。完整範圍與當次結果見 [2026 首次參選查核紀錄](first-run-audit-2026.md)。
`build:candidates` 在人物連結去重後，檢查所有確認資料的年度與身分，再將來源帶入候選人 JSON；不寫入公職任期或修改既有人物經歷。
